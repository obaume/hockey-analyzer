# Report bundle charts are frozen images; re-rendering happens by regenerating the bundle, not inside it

A report bundle chart could have carried a declarative spec plus its underlying computed series, letting a recipient's app redraw it (restyle, theme, print layout) or letting the sender refresh it in place as new data comes in for those games. We decided against both: a report bundle chart is a pre-rendered raster image only, baked at export time, with no spec or series data alongside it. Recipients never redraw a bundle's charts. When the sender wants an updated chart — e.g. after tagging more data for the same games — the only path is generating a brand-new bundle from the live app; there is no in-place refresh or re-render of an already-exported bundle. This keeps "a report bundle shows exactly what the sender saw" as a strict invariant of the file itself, and keeps the bundle format from needing to track chart-library compatibility across app versions.

Rejected alternative: storing a chart spec + series data would have enabled recipient-side restyling and cheaper in-place refreshes, but at the cost of the bundle no longer being a strictly frozen artifact, and of needing the recipient's chart-rendering code to stay compatible with whatever spec version an older bundle used.
