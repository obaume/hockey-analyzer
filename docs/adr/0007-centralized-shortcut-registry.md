# Centralized shortcut registry instead of ad hoc per-widget key bindings

Ticket 13 (video playback shell) is the first of several tickets — 08 and 15 (event-logging hotkeys, `h`/`a` team-scope toggle), 17 (bulk line-change entry) — that each want the app's stated goal of "almost every discrete action has a keyboard shortcut" to hold. We decided against letting each ticket wire its own `QShortcut`/`keyPressEvent` bindings independently: Qt's native ambiguous-shortcut handling silently no-ops when two active bindings collide rather than erroring, so two tickets independently claiming the same key (e.g. `h`) would fail silently at runtime instead of being caught at implementation or review time. Instead, ticket 30 introduces a single shortcut registry that every widget registers (key, scope, action) bindings into; registering a key already claimed by another simultaneously-active scope raises immediately, and a text-entry field taking focus suspends the shortcuts scoped around it until it loses focus. Ticket 13 is blocked on ticket 30 as a result, even though ticket 30 has no video or persistence dependency of its own.

Rejected alternative: ad hoc per-widget bindings would have let ticket 13 proceed immediately without a prerequisite ticket, but would leave every later hotkey addition (08, 15, 17) responsible for knowing the full set of keys already claimed elsewhere in the app — a coordination burden that only grows, and one the registry's registration-time conflict check removes entirely. Keymap customization was explicitly deferred (ticket 30 ships only a hardcoded default keymap), but routing all bindings through one registry now is what keeps remapping possible later without refactoring every widget that owns a shortcut.
