# IIHF and NHL as the two supported rink types, chosen per Game and immutable

`zone`/`high_danger` (see CONTEXT.md's **Rink coordinates**) were originally derived against a single, implicit hardcoded geometry — in practice NHL's 200×85ft rink, the default assumption made while building tickets 15/16, even though the project's actual real-world use case is IIHF rinks (197×98.4ft: notably wider, with blue lines at ±24.6ft and goal lines at ±85.4ft rather than NHL's ±25ft/±89ft). We corrected this to a closed `Game.rink_type` enum (`IIHF`/`NHL`), required at creation with no nullable "unset" state, rather than either leaving NHL as a silent wrong default or hardcoding IIHF with no path to a second rink type — the project is expected to track games from both standards, not just IIHF.

`rink_type` is immutable once the `Game` is created — the only field in this app that isn't edit-anytime. Every other manually-tagged field can be corrected at any point because getting it wrong just means it was momentarily unset or briefly incorrect; `rink_type` is different because it's not a fact *about* an event, it's the geometry every event's already-stored (x, y) coordinate gets *reinterpreted against* on every read. Allowing it to change after tagging begins would silently shift what `zone`/`high_danger` mean for every already-clicked coordinate, with nothing re-clicked and no warning. The correct remedy for picking the wrong rink type is deleting the game and starting over, not an in-place edit.

`domain/rink.py` remains the sole source of truth for both standards' geometry — the rendering library (see ADR-0009) only draws what `domain/rink.py` defines, never the reverse, keeping the domain layer free of any rendering dependency (matching `models.py`'s existing "no GUI or video dependency" boundary).
