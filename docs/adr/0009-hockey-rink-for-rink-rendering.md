# Adopt hockey_rink (GPL-3.0) for rink diagram rendering

The rink-click capture widget (ticket 16) and future static diagrams (e.g. shot charts) both need to draw a rink. We're replacing the hand-rolled `QPainter`-based rendering in `ui/rink_view.py` with the `hockey_rink` library (PyPI: `hockey-rink`), rather than continuing to hand-maintain rink markings ourselves. It conveniently ships ready-made `IIHFRink` and `NHLRink` templates whose measurements match ADR-0008's two supported standards almost exactly, draws richer, more accurate markings (faceoff dots/circles, trapezoid, crease, net) than we were willing to hand-draw, and its coordinate convention (feet, origin at center ice) already matches `domain/rink.py`'s.

The trade-off: `hockey_rink` is matplotlib-based with no built-in interactivity (no click-to-coordinate handling) — we still write our own click capture via matplotlib's `mpl_connect('button_press_event', ...)`, same amount of glue code as before, just against `hockey_rink`'s drawing instead of our own. It's also GPL-3.0 licensed, and this repo will be GPL-3.0 licensed too once distributed. GPL-3.0 doesn't forbid selling the product, but it does mean anyone who receives a distributed copy must also receive the source (or a written offer for it) and the right to redistribute it further, including for free — a straightforward "sell locked-down proprietary copies" model isn't compatible with it once this dependency is in the distributed app. `hockey_rink` is used from the UI layer only, never imported by `domain/` (see ADR-0008) — it renders what `domain/rink.py` already defines as ground truth, and supplies no geometry the domain layer depends on.
